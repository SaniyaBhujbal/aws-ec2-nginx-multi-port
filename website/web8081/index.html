Security & Access Control

Understanding how Linux permissions and SELinux policies protect web server resources.

Security Controls in Practice

CONTROL 01

SELinux Enforcement

Mandatory access control restricts what a service can access, even when ordinary Linux permissions allow access.

CONTROL 02

File Security Contexts

Web content uses the httpd_sys_content_t type so the web server can read appropriately labelled content.

CONTROL 03

Port Policy

SELinux port types help determine which ports a confined web server process may bind to.

Troubleshooting Reference

# Inspect SELinux file labels
ls -lZ /testdata/web8081/index.html

# Inspect allowed HTTP port types
sudo semanage port -l | grep http_port_t

# Define persistent web content labels
sudo semanage fcontext -a -t httpd_sys_content_t "/testdata(/.*)?"

# Apply expected labels
sudo restorecon -Rv /testdata

# Investigate recent SELinux denials
sudo ausearch -m AVC -ts recent

Incident: HTTP 403 Forbidden

Root cause identified in the lab:
SELinux audit records showed Nginx was denied access to index.html files labelled unlabeled_t. The files were relabelled to httpd_sys_content_t and the HTTP endpoints were tested again.

Operational Principle

Diagnose the denial, verify the relevant policy and file context, make the smallest appropriate correction, and confirm access. Keep SELinux enforcing instead of disabling a security control to bypass the problem.
